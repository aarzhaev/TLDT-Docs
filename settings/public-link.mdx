---
title: "Public Link settings"
description: "Control your username, public copy, visitor access, visible models, and profile links."
---

Open **Settings** in the owner sidebar. This page controls how your public profile appears and what visitors can do.

## Public link

Set the username that forms your public address, for example `tldt.me/alex`. The public link can be enabled only when the username and a published Memory version are ready.

Use **Copy link** to share it or **Public page** to open it yourself.

## Visitor options

- **Visitor validation**: require a short visitor form before Chat continues, or leave it optional.
- **Allow interpretation**: allow clearly labeled interpretation and general knowledge in addition to grounded published Memory. When disabled, answers stay limited to published Memory and policy boundaries.
- **Public CV**: show or hide the owner-approved Public CV panel.
- **Starter prompts**: edit the prompt chips shown above the public Chat input.

## Public copy and languages

Edit the header, welcome title, description, and starter prompts separately for English and Russian. The language switch on the public page lets a visitor choose the available language.

Keep the copy specific. Explain what a visitor can ask and what the profile is for; do not promise actions the profile cannot take.

## Models and provider routing

When BYOK is enabled, you can manage the visible model allowlist and choose price- or throughput-oriented provider routing. Visitor choices use only the visible effective list. Provider and model metadata remain owner-only.

## Social links

Add HTTPS links for LinkedIn, X, Instagram, GitHub, Telegram, a website, Cal.com, or a custom labeled link. Invalid links and unlabeled custom links are rejected before save.

<Note>Saving settings changes configuration. It does not expose Private Memory or bypass the separate Memory publication boundary.</Note>
