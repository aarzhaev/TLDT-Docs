Memory Gaps turns missing or weak published evidence into questions you can answer. A gap means the reviewed Memory used for that analysis did not explain something sufficiently. It does not prove that you lack the experience.

## Where gaps come from

| Source | What is reviewed |
| --- | --- |
| **Analyze** in Memory | Your active published Memory, looking for useful details missing from experience it already describes. |
| A newly completed Fast Check | The vacancy requirements and evidence in that check's original Memory version. |
| A completed Simulate | Interview questions, answers, and the Memory version pinned to that simulation. |

Open **Memory** to see the **Memory Gaps** column. On a narrow screen, select the Gaps section. Completed Fast Check and Simulate reports also have an owner-only **Memory Gaps** tab with their findings and a **View all gaps** link.

**Analyze** starts a new review only when you choose it. Opening Memory does not run an analysis. Older completed sessions are not automatically analyzed retroactively. A session created without published Memory cannot be analyzed for gaps later, even after you publish Memory.

## Read the question and its evidence

Select a gap card to open its details. Review the full question, **Why this matters**, missing evidence, and source questions or answers. Links take you to the source report, simulation, or published Memory version.

Several related findings can be attached to one Open card. A finding from an earlier Memory version stays historical: publishing new evidence does not rewrite the source or prove that the finding still applies.

## Add your answer

Use **Your answer**, directly below the question:

- **Type or paste text.** You can write outside TLDT and paste the finished answer. Include what you personally did, the situation, dates or scope where relevant, the result, and any limits on the claim.
- **Dictate.** Use the microphone, allow microphone access, record, and stop. The transcription is appended to the editable answer. Review it before continuing. The recorder stops at ten minutes; shorter recordings are easier to check and upload.
- **Reuse your Manual Simulate answer.** An eligible Manual source offers **Use this answer**. It appends the complete saved answer once, with its source context. Auto answers, interviewer text, and report text cannot be imported as your testimony.

Text autosaves privately. Wait for **Saved** before leaving; this confirms storage, not that the answer is complete or factually sufficient. If saving fails, keep the panel open and retry. If another edit conflicts, review the newer saved answer and choose **Use saved answer** or **Keep both answers**.

Dictation adds text only. It does not send a chat message, generate a Memory change, or publish anything. This field records from the microphone; it is not an audio-file upload or a full interview-recording import. For an existing recording, prepare a transcript and paste the relevant, reviewed answer.

## Turn answers into Memory

Choose **Generate Memory** from the answer or the Gaps column. Select saved answers, then [review the proposed changes through Memory Loop](/memory/loop). Saving an answer alone does not update the twin.

## Manage status yourself

Use the card or detail status menu to move a gap between **Open**, **Closed**, and **Archived**, including reopening it. The source history and saved answer remain attached.

Answering, accepting a proposal, or publishing Memory never closes a gap automatically. Close it when you have checked the issue; archive it when you do not plan to work on it. New findings can match Open cards, while a later finding about a Closed or Archived issue can create a new Open card.

If an analysis fails, inspect its status and use **Retry** where offered. A completed analysis with zero findings is different from a failed or unavailable analysis.
