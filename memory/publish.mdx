**Publish** in the Memory workspace creates an immutable snapshot and makes it active. This is the step that allows reviewed draft changes to affect new answers and checks. [Enabling your public username link](/settings/public-link#set-the-address-and-enable-the-link) is a separate setting.

## Before publishing

Review the current draft's Raw and Derived cards. Mark only the intended documents **Public**, check [special roles](/memory/overview#special-roles), and keep anything that should remain outside the runtime **Private**.

If you used [Memory Loop](/memory/loop), [accept the proposals you want](/memory/loop#review-in-derived-memory) first. Pending, rejected, or outdated proposals are not part of the draft publication. Acceptance alone does not publish them.

## Publish the reviewed version

<Steps>
  <Step title="Choose Publish in Memory">
    Inspect the proposed version, included documents, changes from the previous version, and warnings. This reviews the full Public draft, not only the most recent card you edited.
  </Step>
  <Step title="Resolve warnings and sensitive-content decisions">
    Check missing [Properties](/memory/drafts-and-documents#documents-and-properties), conflicting special roles, and sensitive Public content. High or Restricted documents require an explicit decision. Keep a document Private when it should not be part of published Memory; do not lower sensitivity just to dismiss a warning.
  </Step>
  <Step title="Confirm publication">
    TLDT checks that the reviewed draft is still current, creates the version, and makes it live. If another edit changed the draft during review, refresh and inspect the current version before trying again.
  </Step>
  <Step title="Check Search Profile and test the result">
    Publication reports the separate Search Profile update outcome. If it needs attention, return to **[Profile](/profile#keep-it-current)** to review the context and update it. Test the changed evidence in [Preview](/owner-review/preview), a new [Fast Check](/public-profile/fast-check), or a new [Auto Simulate](/owner-review/simulate#choose-who-answers) session.
  </Step>
</Steps>

A Search Profile update failure does not undo a successful Memory publication. Read the status so you know which action needs retrying.

## Published versions and drafts

A published version is read-only. Changing or deleting its source draft does not rewrite it. To revise the active Memory, [edit a draft](/memory/drafts-and-documents#draft-workspaces) and publish a new version.

Use the versions panel to inspect an earlier snapshot or make it active again. Activating a version changes the runtime source; switching the active editing draft does not. Review Search Profile after switching versions as well.

[Save CV in Profile](/profile) is a narrower publication action available when there is no active published CV. It publishes that CV while preserving the existing published Memory. Normal **Publish** reviews the full Public draft.

## Existing sessions remain historical

Fast Check and Simulate keep the Memory version selected when they were created. Later publication does not rewrite their reports, transcripts, Memory Gap findings, or [saved shares](/sharing#revoke-delete-and-version-behavior). Create a new check or simulation to assess the new evidence.

Gap statuses remain manual. Publishing a better answer does not close a Memory Gap automatically; verify it and [close or archive it yourself](/memory/gaps#manage-status-yourself).

## Public Memory and the public link

You can use active published Memory for private search and preparation while your Public link is off. To let visitors use the twin, review [Public profile settings](/settings/public-link), test it, and enable the link deliberately.

Public documents are eligible to inform public answers when that link is enabled. Hiding the Public CV panel only hides that panel; it does not remove the CV from published Memory. Change the Memory publication when you need to change which evidence the twin may use.
