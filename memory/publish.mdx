Publication creates the immutable Career Memory version that TLDT workflows can use. Activation selects which published version is live.

This boundary protects both preparation and representation: editable drafts can change freely without silently changing Fast Check, Preview, Public Chat, or existing pinned simulations.

## Preview the exact release

Open the publication panel from **Memory**. The preview shows:

- the next version name;
- the exact Raw and Derived files included;
- generated Memory indexes;
- warnings about sensitive Public files;
- changes from the previous version;
- draft and Profile revisions used for the preview.

Read the preview as a release checklist. A document can be Public and still be wrong for this particular version.

## Publish and activate

<Steps>
  <Step title="Resolve document and role warnings">
    Review missing Properties, duplicate special roles, incomplete documents, and sensitivity warnings.
  </Step>
  <Step title="Confirm sensitive content intentionally">
    Public High or Restricted files require an explicit decision. Confirm only material you are prepared to use in the selected workflows.
  </Step>
  <Step title="Publish the immutable version">
    TLDT rechecks that the draft and revisions have not changed during review, then stores the selected content as a version.
  </Step>
  <Step title="Activate when ready">
    Activation moves the public runtime pointer to the new version. Until then, the previous active version continues to power live workflows.
  </Step>
  <Step title="Test the result">
    Use Owner Preview for ordinary public questions, Fast Check for a real vacancy, and Auto Simulate for a role-specific stress test.
  </Step>
</Steps>

## Version behavior

Changing a draft after publication does not change the version. To update live behavior, edit a draft, preview, publish a new version, and activate it. To roll back, activate an older immutable version.

Fast Check and Simulate pin Memory authority at session creation. Activating a newer version does not rewrite an existing report or simulation.

<Warning>
  A successful draft save is not a release. Runtime workflows read only an active or session-pinned published version; they never fall back to the current draft.
</Warning>
