Memory Loop turns your saved answers to Memory Gaps into proposed additions or updates. You review each change before it reaches your draft, then publish the draft separately. This is how useful interview preparation can improve the next search or conversation.

## Generate proposed changes

<Steps>
  <Step title="Save your own answers">
    [Answer one or more gaps](/memory/gaps) with text, dictation, or **Use this answer** from your own Manual Simulate turn. Wait for the saved state.
  </Step>
  <Step title="Check the active draft">
    Memory Loop prepares changes for the draft you are currently editing. Choose the intended draft before starting.
  </Step>
  <Step title="Choose Generate Memory">
    From a gap, its answer is preselected. From the Gaps column, choose one, several, or all filled answers. **Select all** includes saved answers across all pages and Open, Closed, and Archived gaps.
  </Step>
  <Step title="Inspect the result">
    TLDT preserves the selected original answers as Private Raw evidence and reads related Derived Memory. It may propose a new document, add to an existing one, ask for more evidence, or find that no change is needed.
  </Step>
</Steps>

Related answers may become one proposal. Generating does not apply the proposal, publish it, or close a gap. Reopening the panel restores the saved run; a failed run needs an explicit **Retry**.

## Review in Derived Memory

New proposals appear as **Review** cards in Derived Memory. Existing documents with proposed updates also show Review. Open a proposal to inspect its text and Properties. Updates offer **Current** and **Proposed** views so you can check what will be added.

Check who performed the work, dates, scope, outcomes, metrics, and uncertainty. Keep an explicit limitation when the answer does not support a stronger claim. Resolve contradictory information yourself instead of treating generation as an automatic fact checker.

You can edit the proposed text. Saving an edit changes only the proposal. If its Properties become stale, choose **Refresh Properties**, inspect the result, and then accept or reject.

| Action | Result |
| --- | --- |
| **Accept for publication** | Creates a new Public document in the selected draft. It is eligible for a later publication, not live yet. |
| **Accept update** | Applies the proposed update to the existing Public draft document. |
| **Accept private update** | Updates an existing Private draft document and keeps it Private. |
| **Reject** | Discards the proposed change without changing the original document. |

Updates preserve the existing document's visibility and special roles. New documents do not receive a CV, Soul, Boundaries, or Voice role automatically.

## Publish the reviewed result

Use **Publish** in Memory after accepting the changes you want. Review the complete Public draft, including any other pending edits. Confirming publication creates and activates the new version. Unaccepted proposals are not included.

Then check your Search Profile status and test the relevant question in Preview, a new Fast Check, or a new simulation. Existing sessions keep their earlier Memory version. Close the original gap manually when you are satisfied with the result.

## If a proposal is out of date

Changing an answer, its target document, or the working draft can invalidate a pending proposal. Review the current source and generate a new proposal instead of applying an old change over newer work. You can reject an outdated proposal without changing Memory.

If the complete input does not fit, generation stops with an explicit error and preserves your answers. Choose a smaller relevant set for a new run; TLDT does not silently truncate answers or documents.

<Note>
  **Save to Memory** on a simulation preserves its transcript as Raw evidence. Memory Loop is a separate flow that starts from selected saved gap answers and produces reviewable changes. Neither action publishes automatically.
</Note>
