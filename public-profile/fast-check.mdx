Fast Check maps one real vacancy to the evidence in published Career Memory. Use it to prepare for a role, identify what the profile can support, and turn uncertainty into questions for a human conversation.

You can run Fast Check from the owner workspace or, when enabled, from a public profile. Both surfaces use reviewed published Memory rather than editable drafts.

For quick prioritization across a job list, start with [Instant Fit](/jobs/instant-fit). Fast Check goes deeper into one selected role. It does not require you to enable your own public link for private preparation.

## What the report separates

| Signal | Meaning |
| --- | --- |
| Supported fit | Published evidence directly supports a relevant requirement. |
| Partial fit | Some evidence is relevant, but scope, depth, recency, or context remains incomplete. |
| Real gap | Available evidence supports a meaningful mismatch with the role requirement. |
| Missing proof | Published Memory does not contain enough evidence to decide. This is not proof that the owner lacks the experience. |

## Run an owner Fast Check

<Steps>
  <Step title="Open Preparation → Fast Check">
    Create a new check from the owner workspace, or choose **Fast Check** from a Job Search vacancy detail to carry that role into the check.
  </Step>
  <Step title="Add one substantive vacancy">
    Select a saved vacancy, paste one job link, or add the vacancy text. Avoid combining several roles into one check. If the posting cannot be extracted, use the complete relevant description instead.
  </Step>
  <Step title="Review the extracted vacancy">
    Confirm the role, company, location, work model, specialization, and description when the source provides them. Edit the text if the source is incomplete.
  </Step>
  <Step title="Run the diagnostic">
    Choose an available model and start the check. TLDT uses the active published Memory version pinned to the session.
  </Step>
  <Step title="Read the report as preparation">
    Review the summary, evidence, partial coverage, gaps, missing proof, and questions to validate. Use the result to choose what to rehearse or clarify.
  </Step>
</Steps>

## Use the result to prepare and improve Memory

The result lets you inspect the vacancy, published CV context, and diagnostic report. Newly completed checks also feed owner-only [Memory Gaps](/memory/gaps), available in the report's **Memory Gaps** tab. A finding asks for missing published evidence; it is not an automatic edit to your career history.

Answer useful gaps in Memory, then use [Memory Loop](/memory/loop) to review additions. Continue with Simulate to practice difficult requirements or test the twin's answers.

Use **Check again** to create a new diagnostic while keeping the completed report unchanged. The available result actions also let you export Markdown, share a safe snapshot, or delete the check. If you published new Memory, start a new check to assess that version.

## Use Fast Check from a public profile

A visitor can run the same kind of diagnostic when the owner enables the public profile. The report does not imply that the owner reviewed the role, wants the role, or is available. It gives the visitor a structured starting point for a conversation.

The owner may share a completed Fast Check as a visitor-safe snapshot. Revoking the share disables that link without changing the source check.

## What Fast Check does not do

Fast Check does not rank candidates, verify identity, predict hiring or interview outcomes, submit an application, or replace a hiring decision. It also does not convert missing stored evidence into a definitive **no fit**.

<Tip>
  After a check, use Manual Simulate to practice the uncertain parts. Use Auto Simulate to test whether the published AI profile can answer them from the same reviewed evidence.
</Tip>
